# SentinelRAG Project State

## IMPLEMENTED ? integrated static investigation prototype

The CLI connects APK inspection, decompilation coverage, manifest parsing, evidence extraction, threat matching, qualified investigation seeds, source ownership, bounded per-behavior graphs, graph-aware RAG, structured reasoning, deterministic validation and JSON/Markdown reporting.

- Existing evidence enrichment, Accessibility compatibility and ownership hardening are retained.
- `BehaviorInvestigation` packages each behavior's graph, context, retrieval, untrusted reasoning, validation and findings.
- `BehaviorContext` distinguishes LOCAL facts, APK-wide facts, source relationships, local flows, unresolved relationships and coverage limitations.
- A versioned 35-behavior starter catalog supplements existing JSON records. Templates are analyst-authored investigation specifications, not signatures.
- Source/sink labels are separate from proven flows. Broad matches and rejected/duplicate seeds remain reportable.
- Optional Gemini and RAG failure does not suppress deterministic findings. `--no-llm --no-rag` supports offline reports.
- Exact structured claims are validated against supplied canonical IDs/values/edges. Free-form LLM prose is untrusted and does not set final severity, state or family identity.
- Console stages, analysis ID, timings, graph/seed counts and provider statuses are retained in reports.
- JSON and escaped Markdown reports are generated by default. Existing profile flags and extraction commands remain supported.

## PARTIAL ? analysis capability and operational readiness

- Java source resolution is bounded and deliberately conservative. Source ownership is heuristic where marked APPLICATION_CANDIDATE.
- The deterministic flow recognizer supports local user-input/command construction; other source/sink combinations are investigation labels only.
- Coverage reflects decompiler recovery, not complete behavior visibility. Manifest-package implementation counts do not include every relocated manifest component.
- Profile outcomes remain indicator/co-occurrence reviews. The Accessibility compatibility graph may expose declarations while callback edges stay unresolved.
- Generic narrative semantics, runtime execution, malicious intent, exploitability and malware-family attribution are not automatically verified.
- The starter catalog needs per-behavior research citations, labeled examples and false-positive calibration; no exhaustive Android malware corpus is claimed.
- RAG is per-run in-memory retrieval. External tools still need stronger isolation, timeout/resource controls and artifact caching.
